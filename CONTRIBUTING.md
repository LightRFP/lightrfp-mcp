# Contributing

Useful contributions include clearer documentation, minimal client examples, reproducible integration bugs and bond-search scenarios that expose ambiguous results.

For a bug, include the date, client/version, tool name, non-sensitive example inputs, expected behavior and actual behavior. Remove secrets, personal data and application records before posting. Use fictional scenarios where possible.

Check Markdown links and run any changed example before opening a pull request. Do not add generated catalogs, stored application forms, credentials, deployment files or customer data. The catalog and hosted implementation are maintained separately.

Report suspected security issues privately as described in [SECURITY.md](SECURITY.md).

Contributions are made under the applicable [repository licenses](LICENSE.md): MIT for example code and CC BY 4.0 for documentation and illustrations. Only contribute material you have the right to share under those terms.
